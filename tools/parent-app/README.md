# Manara Parents: the console as a Play Store app

The parent console (`controller/`) packaged as an Android app, a Trusted Web Activity (TWA): the
same site, full screen, with its own icon and a Play Store page. Separate from Manara on the
child's phone (`agent/`). Nothing in the console changes: the app opens
`https://manara-rosy.vercel.app/?source=app` and stays on that site.

## Done (2026-11-20 and 21)

1. **The console is installable** (`controller/public/manifest.webmanifest`, `icons/`, `sw.js`,
   which caches no console data, only an offline page). Chrome reports no installability error.
   Parents can already install it from the browser, with no store.
2. **The Android project**, in `android/`, generated by `generate.mjs` with Bubblewrap's own library
   and the answers above (`android/twa-manifest.json` holds them all). Regenerate it the same way if
   the manifest or a value changes:
   ```
   npm install @bubblewrap/core@1.24.1        # once, anywhere outside the repo
   BUBBLEWRAP=<that folder>/node_modules/@bubblewrap/core node generate.mjs
   ```
3. **The build**: an unsigned `app-release.aab` (1 MB):
   ```
   cd android
   set JAVA_HOME=C:\Program Files\Microsoft\jdk-17.0.21.21-hotspot
   set ANDROID_HOME=C:\Users\nbensalah\AppData\Local\Android\Sdk
   gradlew.bat bundleRelease      # app\build\outputs\bundle\release\app-release.aab
   ```
   The first build downloaded Android Build-Tools 35 and Platform 36 into the SDK.

Build output, `.aab` files and keys are ignored by git (`android/.gitignore`).

## Your part, once the Play account is verified

### 1. Create the upload key (once, 5 minutes)

The key that signs what you upload. With Play App Signing (step 3), Google keeps the key that signs
what parents install, so a lost upload key can be replaced; still, keep it safe. It lives **next to
the project, never inside it**, in `C:\Users\nbensalah\projects\manara-keys\`:

```
mkdir C:\Users\nbensalah\projects\manara-keys
"C:\Program Files\Microsoft\jdk-17.0.21.21-hotspot\bin\keytool" -genkeypair -v ^
  -keystore C:\Users\nbensalah\projects\manara-keys\manara-parents-upload.keystore ^
  -alias upload -keyalg RSA -keysize 2048 -validity 10000 -dname "CN=Manara Parents"
```

Choose the password yourself and keep it, with a copy of the `.keystore` file, in your password
manager. Never send either in a chat or put them in the repo.

### 2. Sign the bundle

```
cd tools\parent-app\android
gradlew.bat bundleRelease
"C:\Program Files\Microsoft\jdk-17.0.21.21-hotspot\bin\jarsigner" -sigalg SHA256withRSA -digestalg SHA-256 ^
  -keystore C:\Users\nbensalah\projects\manara-keys\manara-parents-upload.keystore ^
  app\build\outputs\bundle\release\app-release.aab upload
```

### 3. Create the app in Play Console and upload

Play Console → **Create app** → "Manara Parents", app, free. Then:

- **Test and release → Closed testing** → create a track, upload the signed `.aab`, keep
  **Play App Signing** on (the default).
- **App content:** privacy policy `https://manara-rosy.vercel.app/privacy.html`; target audience
  **18 and over** (it is for parents); Data safety and content rating as below; ads: none.
- **Store listing:** the texts below, the icon `controller/public/icons/icon-512.png`, the feature
  graphic `docs/play-assets/feature-graphic-1024x500.png`, and phone screenshots.

### 4. Link the app and the site (Digital Asset Links)

Without this the app shows a browser address bar. Play Console → the app → **Test and release →
App integrity → App signing** → copy the **SHA-256 certificate fingerprint of the app signing key**.
Send it to Claude, or create `controller/public/.well-known/assetlinks.json` yourself:

```json
[{
  "relation": ["delegate_permission/common.handle_all_urls"],
  "target": { "namespace": "android_app", "package_name": "com.manara.parents",
              "sha256_cert_fingerprints": ["<the fingerprint from Play Console>"] }
}]
```

Deploy, then check that `https://manara-rosy.vercel.app/.well-known/assetlinks.json` answers it, and
open the test app: no address bar means the link works.

### 5. Closed test, then production

A recent personal account must run a closed test with **12 testers for 14 days** before production
(check in Play Console whether it applies per app). The 14 days start once 12 testers have joined
through Google's opt-in link: collect the founding families' Gmail addresses during the setup
calls. Then **Apply for production** from the Dashboard. Use the same testers later for Manara
itself (the `play` build), whose review will be much harder (device owner, guided setup).

### Updating the app later

Only when the app itself changes (the icon, the name, a new Android requirement): the console's
content updates on the website as usual, with no new upload. Raise `appVersionCode` and
`appVersionName` in `generate.mjs`, regenerate, build, sign, upload.

>
> Le téléphone de l'enfant utilise l'application Manara, à installer depuis manara-rosy.vercel.app.

**Data safety for this app:** collected: email address (account management), and what the parent
types into the console (rules, the known numbers list). This app itself reads nothing from the
parent's phone. Shared with third parties: no. Encrypted in transit: yes. Deletion: yes, in the
console or at `https://manara-rosy.vercel.app/delete-account.html`. The child's data, which the
parent views, is declared for Manara itself, not this app.

**Content rating:** a utility for parents, no user-generated content shared publicly, no violence;
"shares location with others": yes, the parent sees the child's location when they turn it on.

**Screenshots:** the console at phone width, in French: sign-in, the phone's Rules tab, the
Activity tab, and a setup step, with invented data, as for the videos.
